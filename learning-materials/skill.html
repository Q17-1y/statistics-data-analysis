01 · 它是什么

Skill 是一个文件夹：Agent 在任务匹配时按需加载的"入职手册"。

个人解释

我觉得它让 AI 更加智能、专业。如果把我们的生活比作一台巨大的仪器，Skill 就是那位专业的介绍人员——仪器中的任何一个零件，他都心知肚明。

05 · 应用场景与边界

具体应用场景

给课程学习装一个 skill：写一份 stats-study，把"笔记命名规范、每周要点模板、代码目录约定"沉淀进去。以后每次让 Agent 写学习笔记，它自动按规范执行——不用每轮重复交代规则。（本仓库的 concept-origin-study 就是一例）

容易混淆 / 使用边界

易混淆点澄清
Skill ≠ MCPMCP 提供"连接"（接外部工具和数据，工具定义常驻上下文）；Skill 提供"知识"（元数据常驻、正文按需）。官方定位：互补
Skill ≠ 插件程序Skill 主体是 Markdown 指令而非代码逻辑；脚本是可选附带的确定性工具
安全边界Skill 能赋予 Agent 执行代码的能力，恶意 Skill 可致数据外泄——只装可信来源，安装前审计捆绑文件

★☆☆☆☆
1. 一个 Skill 的最小组成是什么？
Skill 的本质是文件夹 + SKILL.md，其余内容都是可选的。验证 ↗
★★☆☆☆
2. SKILL.md 的 frontmatter 中，哪两个字段是必填的？
规范最低要求：name（≤64字符，须与文件夹同名）和 description（≤1024字符）。验证 ↗
★★★☆☆
3. SKILL.md 的正文（Markdown 指令部分）何时被 Agent 加载？
启动时只载入元数据；正文在激活时读入；捆绑文件在执行时按需读取——三层递进。验证 ↗
★★★★☆
4. 为什么官方强调 description 字段最值得花时间打磨？
工程博客明确指出：Claude 依靠这两个元数据字段决定是否触发 Skill。写不清楚 = 永远不被用上。验证 ↗
★★★★★
5. 为什么捆绑的 Python 脚本"不进入上下文窗口"反而是优势？
工程博客举例：让模型逐 token 生成一个排序列表，比直接运行排序算法成本高得多；且代码结果确定、可重复。验证 ↗
