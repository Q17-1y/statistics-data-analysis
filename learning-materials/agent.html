Agent（智能体）

一句话：在循环中感知环境、使用工具、自主决策的系统  ｜  全部内容可点击出处验证

01 · 它是什么

Agent 是能自主决定"下一步做什么"的系统——不是一次问答，而是一个循环。

经典框架：LLM 当大脑，规划、记忆、工具三件套补齐能力 —— Lilian Weng 原文 ↗

个人解释 · 初稿（请用自己的话改写后使用）

我觉得 Agent 就像被给了工具箱和目标的实习生：不逐步听指令，而是自己拆解任务、动手尝试、看结果再调整。它和普通聊天的区别在于——聊天是"问一句答一句"，Agent 是"给个目标，它自己走完全程"。

03 · 核心机制：环境反馈循环

Anthropic 的最小定义：Agent 就是"在循环中基于环境反馈使用工具的 LLM"。

要点：每步从环境拿"ground truth"评估进展；需设停止条件（如最大迭代次数）—— 原文 ↗

04 · 最小示例：ReAct 循环

Thought: 我需要先查一下 X 的最新数据     # 思考
Action: search("X 最新数据")             # 行动：调用工具
Observation: 查询结果……                  # 环境反馈
Thought: 结果显示……接下来……             # 再思考，循环

实验结论：带 Thought 步骤的 ReAct 优于纯行动基线 —— 原文综述 ↗

05 · 应用场景与边界

具体应用场景

让编码 Agent 修复一个 bug：它自己读代码、跑测试、看报错、改代码、再跑测试——循环到测试通过为止。人只给目标，不指挥每一步。（官方参考实现：SWE-bench 编码 Agent —— 原文 ↗）

容易混淆 / 使用边界

易混淆点澄清
Agent ≠ 聊天机器人聊天是一问一答；Agent 自主决定流程，可能有几十步
Agent ≠ WorkflowWorkflow 的路径是代码写死的；Agent 的路径由 LLM 现场决定
不是越自主越好Agent 用延迟和成本换表现；错误会累积；必须设停止条件并在沙盒测试
