# Concept Origin Study

从概念的原始出处出发，产出一份克制、可视化、可验证、带递增难度测试的单文件 HTML 学习资料。

## 设计原则（不可妥协）

1. **少即是多**：正文以图代文，每节文字不超过 3-5 行
2. **视觉克制**：全页只用一个强调色 + 中性色；不用装饰性图标；SVG 图形用圆角矩形、圆点、连线
3. **低认知负荷**：每屏聚焦一个概念；编号分节；一句话定义放最前
4. **可验证**：时间线节点、错题解析、页首页尾都必须有指向一手来源的可点击链接

## 输入信息

- **必需**：一个概念名称（如 Agent、上下文窗口、Skill）
- **可选**：学习者指定的侧重点、已知来源、希望的语言

不依赖概念之外的上下文——对新概念同样适用，不做一次性定制。

## 工作流

### 第 1 步：追溯源头

用 WebSearch 检索该概念的"原始出处"——首次提出者、官方发布公告、原始论文/工程博客/正式规范。判断标准：作者是最初提出者、日期最早、含完整技术细节。至少确认 2-3 个一手来源（官方公告、规范原文、原始论文），再补 1 个高质量第三方视角（可选）。

用 WebFetch 逐个抓取一手原文（遇到重定向跟随新 URL），提取：定义、设计动机、核心机制、关键约束/数字、官方类比、最佳实践。所有技术细节必须来自一手来源，禁止凭记忆填充。

### 第 2 步：提炼核心

把资料压缩为：1 句话定义、1 张结构图、1 条时间线（2-4 个节点）、1 个核心机制图、1 个最小示例。总量控制在 6 节以内——删减比添加更重要。

### 第 3 步：生成 HTML

复制 `assets/concept-study-template.html`，逐个替换 `{{占位符}}`：

- 设计系统（CSS 变量、字体、判分 JS）直接复用，不重写
- SVG 图按模板内 TODO 注释的规范绘制（viewBox 宽 640、每处文字一行、强调色只标关键部分）
- 测试题 5 道、难度递增（★→★★★★★）：第 1 题识别题、第 2-3 题细节/机制题、第 4 题设计理由题、第 5 题权衡/反直觉题；每题解析附「验证 ↗」链接
- 文件保存到目标目录，命名 `{概念英文名}.html`

## 输出结构（每份资料必须包含）

| 节 | 内容 | 要求 |
|----|------|------|
| 01 它是什么 | 一句话定义 + 结构图 + **个人解释初稿** | 个人解释标注"初稿，请用自己的话改写" |
| 02 它从哪来 | 时间线，节点带原文链接 | 至少 2 个一手来源 |
| 03 核心机制 | 一张机制图 + 关键约束数字 | 数字须可溯源 |
| 04 最小示例 | 可直接照抄的代码/格式 | 来自官方文档或规范 |
| 05 应用场景与边界 | 1 个具体应用场景 + 易混淆概念/使用边界 | 混淆对象用对比表或并列表述 |
| 06 测试 | 5 道递增难度选择题 | 每题解析附「验证 ↗」链接 |

## 资料来源要求

1. 只引用一手来源（提出者的公告/论文/规范），第三方来源仅作补充视角
2. 所有链接必须真实可访问（生成前逐一抓取核实），禁止伪造或凭记忆拼凑 URL
3. 技术细节（数字、字段约束、定义）以一手来源为准；来源之间冲突时注明差异

## 自检要求

生成后逐项检查：

1. 每个 `{{占位符}}` 都已替换
2. 每条技术断言都能在页内找到对应原文链接
3. 全页只有一种强调色；无装饰性图标
4. 测试题 data-answer 序号与正确选项一致（从 0 数起）
5. 「个人解释」明确标注为初稿，提示学习者用自己的话改写（AI 生成内容不得直接当作最终个人解释提交）
